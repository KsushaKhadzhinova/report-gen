# Инструкция: как собрать отчеты «Электронный бизнес» (NotaCode) по СТП БГУИР

Для нового ассистента. Читать целиком перед работой. Результат: восемь отчетов (ЛР1, ЛР2-3, ЛР4, ЛР5, ЛР6, ЛР7, резюме проекта, финальный отчет ЛР1-7) в DOCX и PDF, которые проходят аудит `report-gen lint` без ошибок и предупреждений и выглядят так, как требует владелица.

## 1. Где что лежит

| Что | Путь |
|---|---|
| Программа `report-gen` | `E:\report-gen` (установлена командой `pip install -e`, команда `report-gen` доступна в оболочке). Рабочая ветка с правилами из этой инструкции: `fix/formatting-sources-object-text` |
| Репозиторий отчетов | `E:\ИИТ\ЭлектронныйБизнес`, удаленный репозиторий `github.com/KsushaKhadzhinova/E-Business` |
| Оригиналы отчетов (их нельзя менять) | `СДАЧА\ЛР1 ... ЛР7`, `СДАЧА\ЛР7\РЕЗЮМЕ_ПРОЕКТА_NotaCode.docx`, `СДАЧА\Финальный_отчет` |
| Готовые файлы на проверку | ветка `ПРОВЕРИТЬ-ОТЧЕТЫ`, папка `ПРОВЕРИТЬ_ОТЧЕТЫ` (DOCX, PDF, README с таблицей статусов) |
| Готовые абзацы после таблиц и рисунков | `СБОРКА\notes_all.json` в ветке `ПРОВЕРИТЬ-ОТЧЕТЫ` (140 штук, ключи привязаны к содержимому таблиц и рисунков) |
| Правила работы владелицы | `HANDOFF.md` в корне репозитория отчетов и память проекта; для кода еще `docs\NEXT_CHAT.md` |

Нужны: Windows, Microsoft Word (работа через COM), Python 3.11 с `python-docx`, `pymupdf`, `pyyaml`. Excel тут не нужен.

## 2. Что требует владелица (проверено на страницах, не менять без ее слова)

Оформление:
- Поля 30/15/20/20 мм, Times New Roman 14, интервал 18 пт, абзацный отступ 1,25 см, по ширине.
- Слева и справа у основного текста, списков и записей источников отступов нет (раньше съезжали поля из-за стилей `Compact` и `Block Text`).
- Курсивом набирается вся латиница и только она. Кириллица, цифры, знаки препинания и пробелы прямым шрифтом, в том числе рядом с латиницей («UML-диаграмма»: `UML` курсивом, `-диаграмма` прямо).
- Списки с тире заменяются нумерованными списками с цифрами без скобки и точки: «1 текст», «2 текст». Нумерация идет заново в каждом списке.
- Список использованных источников: по образцам ВАК РБ, номера в квадратных скобках: «[1] Заглавие [Электронный ресурс] : сведения. – Режим доступа: адрес. – Дата доступа: дд.мм.гггг.». Без тире и курсива, по левому краю (иначе длинные адреса растягивают строки), адреса переносимы. Ссылки в тексте тоже `[1]`.
- Заголовки разделов прописными в тексте и в содержании, заголовки приложений по центру, «Минск 2026» без месяца.
- Таблицы: шрифт 12 пт, пустая строка до подписи и после таблицы, подпись слева над таблицей, шапка повторяется, длинные таблицы режутся с подписью «Продолжение таблицы N». Небольшие (до 4 строк) таблицы не разрываются, у больших шапка и две первые строки остаются с подписью. Столбцы с номерами и датами не должны рваться на «1 / 6».
- Рисунки не обрезаются, подпись по центру.
- Нет «ё» (везде «е»), длинное тире заменено коротким «–», никаких пометок об ИИ в текстах, коде и коммитах.

Текст вокруг таблиц и рисунков:
- Перед каждой таблицей и рисунком обязательно текст со ссылкой на них («в таблице 6», «на рисунке 2»). Если абзац перед объектом оканчивается двоеточием, в него вставляется «(таблица N)». Иначе перед подписью ставится отдельное предложение со ссылкой, которое держится с подписью на одной странице.
- После каждого объекта короткий абзац текста по существу, который не повторяет подпись и ссылку. Формальных вставок «приведены в таблице» после объектов быть не должно.

## 3. Как устроен конвейер

```
СДАЧА (оригинал .docx)
   │  report-gen notes      → данные таблиц и рисунков, после которых нет текста (JSON + картинки)
   │  (абзацы пишет автор по данным, проверка scripts/check_notes.py)
   │  report-gen fix  --notes notes_all.json --drop-source ... → fixed.docx   (весь стандарт, текст вокруг объектов, курсив, списки, источники)
   │  scripts/word_finalize.ps1 → делит длинные таблицы («Продолжение таблицы»), обновляет содержание, сохраняет DOCX и PDF
   │  report-gen lint --docx    → аудит
   ▼
ПРОВЕРИТЬ_ОТЧЕТЫ (DOCX + PDF + README)
```

Пакетный запуск всех этапов для одного или нескольких отчетов: `scripts/finalize_reports.py`. Параметры отчетов (какие источники убрать, как сдвинуть ссылки `[1–3]`) заданы в самом скрипте: `DROP_SOURCE`, `EXTRA_OPTIONS` (ЛР1, ЛР5, ЛР7: сдвиг на 3 и удаление ссылок 1–3; ЛР6: удалить ссылки 6 и 7).

## 4. Пошаговая сборка

Все команды из каталога `E:\report-gen`. Папку результата выбирайте КОРОТКОЙ (например `E:\rb`): Word не открывает файлы по путям длиннее 260 знаков и молча возвращает пустой документ (в скрипте это видно как `InvokeMethodOnNull`). Не используйте для результата временную папку профиля.

1. Проверить состояние: `git status`, `python -m pytest -q`, `ruff check src tests scripts`, `report-gen doctor` (для DOCX и PDF через Word нужен только установленный Microsoft Word).
2. Абзацы после таблиц и рисунков. Готовый файл уже есть: `СБОРКА\notes_all.json`. Он подходит, пока оригиналы в `СДАЧА` не менялись: ключ = подпись + отпечаток содержимого таблицы или картинки. Если содержимое таблицы изменилось, ключ меняется и абзац для нее надо написать заново:
   - выгрузить данные: `report-gen notes <оригинал.docx> --output todo.json --images-dir images` (по одному оригиналу);
   - написать абзацы (можно параллельными агентами по 20-30 объектов; каждому дать файл с данными и требования из раздела 2); запросить результат как JSON-список `{"key": "...", "text": "..."}`;
   - проверить: `python scripts/check_notes.py <абзацы.json> <todo.json>`; исправлять, пока не будет «ОК»;
   - объединить в один словарь ключ → текст (`notes_all.json`).
   Требования к абзацу: 1-2 предложения до 45 слов; только факты из таблицы (числа, названия) или то, что видно на рисунке; безличный научно-деловой стиль; без «ё» и длинного тире; не начинать со слов «Таблица» и «Рисунок»; не повторять подпись.
3. Сборка. Для каждого отчета свой процесс, лучше запускать их параллельно и отсоединенно, чтобы они пережили перезапуск сеанса:
   ```powershell
   $env:PYTHONIOENCODING = 'utf-8'
   foreach ($t in 'ЛР1','ЛР2-3','ЛР4','ЛР5','ЛР6','ЛР7','РЕЗЮМЕ','1-7') {
     Start-Process python -ArgumentList @('scripts/finalize_reports.py','E:/ИИТ/ЭлектронныйБизнес/СДАЧА','E:/rb','--only',$t,'--force','--notes','<путь>/notes_all.json') -WorkingDirectory 'E:\report-gen' -RedirectStandardOutput "E:\rb\log_$t.txt" -RedirectStandardError "E:\rb\err_$t.txt" -WindowStyle Hidden
   }
   ```
   Время (на 8 параллельных процессах Word): резюме 2 мин, ЛР5/ЛР6 4 мин, ЛР7 8 мин, ЛР4/ЛР1 20 мин, ЛР2-3 25 мин, финальный 1-7 около 1 часа 15 минут. Результат: `E:\rb\<имя>\<имя>.docx` и `.pdf`; в логе строка со страницами, числом разбиений таблиц и результатом аудита. Дожидайтесь по логам, не опрашивайте чаще раза в минуту.
4. Послеобработка. Word при сохранении склеивает соседние фрагменты текста, и в одном-двух местах курсив может не совпасть с латиницей. Проверить: `report-gen lint --docx <файл.docx>`; если есть ошибка про курсив: `python scripts/post_fix.py <файл.docx>`, затем обновить PDF: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\refresh_word.ps1 <файл.docx> <файл.pdf>`. Аудит всех восьми: `report-gen lint --docx ...` должен давать «Ошибок: 0, предупреждений: 0».
5. Проверка глазами (обязательна): отрисовать страницы из PDF (`pymupdf`, `page.get_pixmap(dpi=85).save(...)`) и посмотреть: титул, содержание, страницу с нумерованным списком, таблицей с продолжением, рисунком, «Выводы», список источников, приложение. Смотреть: перед объектом есть ссылка, после него абзац, поля не съехали, латиница курсивом, номера в столбцах не рвутся, нет больших пустых мест перед таблицей (пустое место в конце раздела нормально: разделы начинаются с новой страницы).
6. Копирование: `E:\rb\<имя>\<имя>.docx/.pdf` в `ПРОВЕРИТЬ_ОТЧЕТЫ\` под именами `ОТЧЕТ_ЛР1_NotaCode.docx` и т.д. (резюме: `РЕЗЮМЕ_ПРОЕКТА_NotaCode`, финальный: `ОТЧЕТ_по_лабораторным_работам_1-7_NotaCode`). Обновить таблицу страниц и аудита в `ПРОВЕРИТЬ_ОТЧЕТЫ\README.md`.
7. Коммит в репозитории отчетов и, если владелица разрешила, отправка (раздел 6).

## 5. Ловушки, на которых уже теряли время

- Путь длиннее 260 знаков: Word возвращает `null` вместо документа (см. раздел 4).
- Word открывает файл «только для чтения» (`Save()` падает): сохранять через `SaveAs2` во временный файл и подменять оригинал; PDF экспортировать по полному пути с обратными косыми чертами (`GetFullPath`). Так сделано в `scripts\refresh_word.ps1`.
- Параллельно работает до восьми экземпляров Word, это нормально. Зависшие экземпляры закрывайте только свои: по `Get-CimInstance Win32_Process` отбирать процессы с `finalize_reports.py` или `word_finalize.ps1` в командной строке. Не делать `Stop-Process -Name python`: рядом работают служебные процессы среды.
- `report-gen fix` каждый раз начинает с оригинала из `СДАЧА`, а не с готового файла: так результат воспроизводим. Не пытайтесь «исправлять» уже собранный файл повторным `fix`.
- В `python-docx` элементы lxml живут, пока на них есть ссылки: при сравнении `id(element)` держите список абзацев в переменной (иначе `id` совпадет случайно или не совпадет).
- Правки файлов надежнее делать небольшим скриптом на Python: heredoc в оболочке портит обратные косые черты в регулярных выражениях (проверяйте результат печатью `repr`).
- Если после сборки в строке повторяющейся шапки таблицы «ID» стоит не курсивом: это поведение Word при `Rows.Add`; в `word_finalize.ps1` курсив шапки копируется из первой части таблицы.
- Файлы на GitHub в ветке `ПРОВЕРИТЬ-ОТЧЕТЫ` могли обновиться другим сеансом: перед отправкой `git fetch`. Если на сервере есть чужие коммиты с теми же файлами, слияние бинарных DOCX невозможно: владелица разрешала «перезаписать в ветке», это делалось слиянием `git merge -s ours FETCH_HEAD` и обычной отправкой, без `--force`.
- Лимиты использования: перед запуском агентов вызвать `get_usage`; при недельном лимите 70 % и выше агентов не запускать, при 85 % только легкие действия. Сборка в Word лимит не расходует.

## 6. Коммиты, GitHub, приватность

- Коммиты от имени владелицы, без строки соавтора, сообщения в формате `тип: что сделано` на английском, без точки в конце.
- Отправка на GitHub только после явного слова владелицы («загрузи», «пушь»). Обычный `git push`, без `--force`. Перед отправкой в репозитории отчетов выполнить поиск по `*.md` и `*.py` тем набором слов, который записан в `HANDOFF.md` (раздел «Известные нюансы», пункт про пометки ИИ): находок быть не должно. В самих инструкциях эти слова не писать.
- В `report-gen` перед коммитом: `python -m pytest -q`, `ruff check src tests scripts`, `python scripts/check_secrets.py --all`.
- Ключи доступа и личные данные в репозиторий не попадают (`.env`, `profile.enc`).

## 7. Известные ограничения и решения владелицы

- Нужен только Word на Windows; сборка PDF идет через экспорт из Word, а не через LaTeX.
- Формулы в отчетах отсутствуют (проверено), правила для них в `report-gen` пока нет.
- Абзацы после таблиц написаны по данным таблиц и проверены автоматически на совпадение чисел и названий, но владелица должна их прочитать: отчет идет под ее именем.
- Латиница курсивом везде, включая адреса в списке источников. Если владелица захочет адреса прямым шрифтом, правится функция `fix_italics` (исключение для `https://...`).
- Предложения со ссылкой перед объектами формальные («Данные по теме «…» приведены в таблице N»), четыре варианта для таблиц и три для рисунков чередуются (`src/reportgen/domain/object_sentences.py`).
- Пустые места в конце разделов нормальны: разделы начинаются с новой страницы.
