# Продолжение работы в новом чате с ИИ-ассистентом

Этот файл даёт ассистенту всё, что нужно, чтобы продолжить разработку с того места, где остановились. Он не содержит личных данных и ключей.

## Как начать новый чат

Откройте папку проекта в среде с ассистентом, приложите этот файл и напишите:

> Прочитай docs/NEXT_CHAT.md, проверь состояние командами из раздела «Проверка состояния» и продолжи с раздела «Что осталось». Работай по очереди, после каждого шага делай коммит.

Личные сведения владельца (пути к его учебным проектам, предпочтения) ассистент получает от владельца в самом чате и в репозиторий не записывает.

## Архив контекста

Полный ход работы, решения владелицы, статусы отчётов и все материалы, которые она давала (стандарты, курсовые, статьи, оригиналы отчётов), лежат в ветке `context-archive`: https://github.com/KsushaKhadzhinova/report-gen/tree/context-archive. Начните с `archive/README.md` в этой ветке. Ветка временная и содержит личные материалы владелицы; после завершения проекта она будет удалена, и тогда ассистент работает только по этому файлу и коду. Из архива ничего не копируется в `main`.

## О проекте

`report-gen` — генератор пояснительных записок и отчётов по стандарту предприятия БГУИР. Из одного источника (Markdown) собирает DOCX, LaTeX и PDF. Запускается из терминала или в браузере без ассистентов; текст пишет языковая модель (облачная бесплатная по умолчанию, Gemini, локальная Ollama или любой OpenAI-совместимый сервер).

Режимы: курсовая по стандарту, отчёт по лабораторной по заданию, структура по образцу, исправление готовых DOCX, скриншоты (веб, окна, консоль, диаграммы), проверка совпадений с эталонными работами с автопереписыванием, профиль стиля, инкрементальная сборка, веб-интерфейс с кнопками.

Главная идея: стандарт предприятия является ядром. Программа знает его правила (свод в репозитории плюс локальный индекс PDF владельца), сама проверяет результат, а недостающие данные не выдумывает, а помечает `[УТОЧНИТЬ: …]`.

## Архитектура

Чистая архитектура, зависимости направлены только внутрь.

| Слой | Папка | Содержимое |
|---|---|---|
| Предметная область | `src/reportgen/domain/` | блоки и разметка, нумерация, константы стандарта (`enterprise_standard.py`), правила линтера, поиск совпадений, профиль стиля, титульный лист, индекс стандарта, структура и каталог запросов, редактор секретов |
| Сценарии | `src/reportgen/application/` | написание, сборка, проверка, исправление, скриншоты, обучение стилю; порты в `ports.py` |
| Инфраструктура | `src/reportgen/infrastructure/` | клиент моделей, рендереры DOCX и TeX, компилятор LaTeX, аудит и правка DOCX, чтение файлов, захват экрана, хранилища, анализ кода |
| Интерфейс | `src/reportgen/interface/` | `cli.py`, `web.py`, `container.py` (сборка зависимостей), первый запуск, проверка окружения |

Данные: `src/reportgen/data/` (`models.yaml`, структуры `coursework.yaml` и `lab.yaml`, `guidelines/` со сводом правил стандарта, правилами письма и шаблонами запросов, `ui/index.html`).

## Принципы работы над кодом

- Чистый код и чистая архитектура; небольшие функции, говорящие имена, без «ИИ-комментариев»; имена только английские (без транслита русских слов).
- Новая логика покрывается тестами в `tests/` по слоям; приложение тестируется на фейках портов.
- Перед коммитом: `python -m pytest -q`, `ruff check src tests scripts`, `python scripts/check_secrets.py --all`.
- Коммиты от имени владельца, без строк соавторства; сообщения в формате `тип: что сделано`.
- Один шаг за раз, ничего тяжёлого без необходимости (Docker, локальные модели).
- Правки файлов надёжнее делать небольшим скриптом на Python: heredoc в оболочке портит обратные слеши, а многие файлы с окончаниями CRLF (читать с заменой `\r\n` на `\n`, писать байтами).

## Безопасность и приватность (обязательно)

- Ключи доступа хранятся в защищённом хранилище системы или в `.env`; `.env`, `unlock.txt`, `profile.enc` и каталог `workspace/` исключены из git. Ассистент не читает и не выводит эти файлы и значения ключей.
- Личные данные владельца (ФИО, факультет, кафедра) лежат только локально в `workspace/profile.yaml`; в репозитории только заглушки.
- Тексты автора не отправляются моделям; профиль стиля хранит только статистику.
- Перед отправкой моделям из запросов и ошибок вырезаются ключи и токены.
- В папках чужих учебных проектов, которые владелец даёт для чтения, ничего не создавать и не менять; результаты складывать в отдельные папки.
- `scripts/check_secrets.py` блокирует `.env`, личные файлы и токены в коммитах (хук `.githooks/pre-commit`, в CI режим `--all`).

## Что уже сделано

- Генерация DOCX, LaTeX, PDF; один титульный лист по образцу университета для обоих форматов.
- Провайдеры моделей с цепочками резервных моделей по ролям (`writer`, `rewriter`, `reviewer`, `vision`, `utility`), повтор при лимитах, увеличение лимита токенов при обрыве.
- Свод правил стандарта, правила письма и шаблоны запросов; подстановка в запрос выдержек из локального индекса стандарта (поиск BM25 по пунктам).
- Линтер по стандарту: объём введения и заключения, источники (Википедия, порядок и наличие ссылок), приложения, числа и единицы, тире, личные местоимения, ссылки на рисунки и таблицы, метки `[УТОЧНИТЬ]`.
- Исправление готовых DOCX: поля, шрифт, отступ, интервал, заголовки, подписи таблиц; аудит с отчётом.
- Структура по образцу (только заголовки и объёмы; список источников защищён, приложения пропускаются).
- Скриншоты, проверка совпадений, профиль стиля, инкрементальный пересбор, веб-интерфейс (`report-gen ui`: только 127.0.0.1, токен, белый список действий).
- Автоматический цикл «написать, проверить, исправить»: линтер находит замечания, модель переписывает только проблемные разделы (до двух раундов), недостающие факты остаются метками `[УТОЧНИТЬ]`.
- Сводка проекта для модели содержит реальные имена файлов по папкам (миграции, сидеры, тесты, конфигурация) и не учитывает каталоги покрытия и сборки.
- CI/CD: линтер, скан секретов, тесты на Python 3.10 и 3.12, сборка образа и демо-отчёта в Docker, релиз по тегу `vX.Y.Z` (пакет, образ в GHCR, GitHub Release), Dependabot.

## Технические заметки

- Имена макросов LaTeX в `tex_renderer.py` начинаются с `report` и обязаны быть уникальными: совпадение с командой LaTeX (так было с `\\endash`) ломает сборку PDF, а локально это не проверяется (нужен Docker или XeLaTeX); тест следит, чтобы объявленные макросы использовались.
- Если у бесплатного провайдера исчерпан дневной лимит, клиент сразу сообщает время сброса (заголовок `X-RateLimit-Reset`) вместо долгих повторов; уже написанные разделы сохраняются, команду можно повторить позже.
- Бесплатные модели облачного провайдера ограничены по числу запросов в минуту и в день; reasoning-модели тратят токены на размышления, поэтому лимит токенов у раздела большой (6000), при обрыве он удваивается до 16000.
- Список бесплатных моделей меняется со временем; роли имеют резервные цепочки. Свой список можно положить в `workspace/models.yaml`.
- Свои правила и шаблоны запросов можно положить в `workspace/guidelines/`: файлы с теми же именами заменяют встроенные.
- MiKTeX на Windows может зависать при первой сборке без лога; PDF надёжнее собирать в Docker-образе (XeLaTeX и шрифты Liberation внутри).
- `ruff` закреплён набором правил в `pyproject.toml`, чтобы результат не зависел от версии.
