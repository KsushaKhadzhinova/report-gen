# report-gen

Генератор пояснительных записок и отчётов по стандарту предприятия БГУИР. Из одного источника собирает три файла: **DOCX**, **LaTeX** и **PDF**.

Запускается из терминала или IDE, без ассистентов вроде Claude Code. Текст пишет языковая модель (по умолчанию бесплатная облачная), оформление выполняет программа по правилам стандарта.

## Что умеет программа

| Возможность | Команда |
|---|---|
| Курсовой проект: введение, анализ, проектирование, разработка, руководство, заключение | `make`, `write` |
| Отчёт по лабораторной по файлу задания | `lab` |
| Структура по образцу чужого отчёта (берутся заголовки и объёмы, текст образца не копируется) | `from-sample` |
| Исправление готового DOCX: поля, шрифт, отступы, интервал, заголовки, подписи таблиц; переписывание совпадающих абзацев; разбор замечаний руководителя | `fix` |
| Скриншоты: веб-страницы, окна, вывод консоли, диаграммы Graphviz и PlantUML | `shots` |
| Проверка по стандарту: ссылки на рисунки, таблицы и приложения, порядок и состав источников, объём введения и заключения, числа, тире | `lint` |
| Поиск совпадений с эталонными работами и автоматическое переписывание | `overlap` |
| Свой индекс стандарта: поиск пунктов и подстановка нужных в запросы к модели | `stp` |
| Профиль стиля по вашим работам (только статистика, тексты не сохраняются) | `style learn` |
| Пересборка только изменившихся разделов | `write`, `make` |

## Быстрый старт

### Вариант 1: Docker (рекомендуется, работает на Windows, Linux и macOS)

Нужен только [Docker](https://www.docker.com/products/docker-desktop/) и Git.

```bash
git clone https://github.com/KsushaKhadzhinova/report-gen.git
cd report-gen
cp .env.example .env          # Windows: copy .env.example .env
docker compose build          # первый раз занимает несколько минут: ставится TeX Live
```

Запуск любой команды:

```bash
./report-gen.sh start         # Linux и macOS
report-gen.cmd start          # Windows
```

При первом запуске программа проведёт короткое обучение: выбор модели, ключ, ваши данные для титульного листа, проверка окружения.

### Вариант 2: без Docker

Нужен Python 3.10 или новее.

```bash
pip install -e ".[capture]"
report-gen start
```

DOCX и TeX соберутся сразу. Для PDF нужен XeLaTeX и шрифты Times New Roman или Liberation Serif; проще собрать PDF через Docker (`docker compose build`). Скриншоты веб-страниц требуют `playwright install chromium`.

## Ключи доступа: где взять и куда вставить

Чтобы писать текст, программе нужен ключ одного провайдера моделей. Все три варианта бесплатные. Ключ это пароль: никому не показывайте, не вставляйте в чаты и файлы, которые попадают в git.

### Вариант А: OpenRouter (по умолчанию)

1. Откройте <https://openrouter.ai> и зарегистрируйтесь (кнопка Sign in, можно через Google или GitHub).
2. Откройте <https://openrouter.ai/keys>, нажмите **Create Key**, дайте имя (например, `report-gen`), лимит расходов можно оставить нулевым: используются бесплатные модели.
3. Скопируйте ключ (начинается с `sk-or-`). Он показывается один раз.
4. Вставьте ключ одним из способов:
   - **Без Docker, рекомендуется:** `report-gen key set cloud` и вставьте ключ в скрытое поле. Он сохранится в защищённом хранилище системы (Windows Credential Manager, macOS Keychain, Secret Service в Linux) и нигде не лежит открытым текстом.
   - **С Docker:** откройте файл `.env` в папке проекта, впишите после знака равенства `OPENROUTER_API_KEY=sk-or-...` (без кавычек и пробелов) и сохраните. Внутри контейнера системного хранилища нет, поэтому ключ передаётся через `.env`. Файл `.env` не попадает в git, не показывайте его другим.
   - **Если ключ уже в `.env` и хранилище есть:** `report-gen key import-env` перенесёт его в хранилище и очистит значение в файле.
5. Проверка: `report-gen key status` (покажет «задан» или «не задан», сам ключ не выводится) и `report-gen models --check`.

Бесплатные модели OpenRouter ограничены по числу запросов в минуту и в день; при превышении программа ждёт и пробует резервные модели.

### Вариант Б: Google Gemini

1. Откройте <https://aistudio.google.com/apikey> и войдите аккаунтом Google.
2. Нажмите **Create API key** и скопируйте ключ.
3. Вставьте: `report-gen key set gemini` или строка `GEMINI_API_KEY=...` в `.env`.
4. Переключитесь: `report-gen use gemini`.

### Вариант В: локальная модель (без ключей и интернета)

Работает на вашем компьютере, но нужна мощная видеокарта или много терпения.

```bash
docker compose --profile local up -d ollama
docker compose exec ollama ollama pull qwen2.5:7b
report-gen use local
```

### Любой другой сервер с OpenAI-совместимым API

В `.env` укажите `REPORTGEN_BASE_URL=https://адрес/v1` и `REPORTGEN_API_KEY=...`, затем `report-gen use custom`.

Вернуться к облачным моделям: `report-gen use cloud`. Список моделей по ролям: `report-gen models`.

## Ваши данные для титульного листа

Ваши ФИО, факультет и кафедра хранятся только на вашем компьютере, в `workspace/profile.yaml`; этот каталог исключён из git.

```bash
report-gen profile set        # спросит студента, руководителя, факультет, кафедру
report-gen profile show
```

Пока данные не заданы, на титульном листе стоят заглушки: `<И.О. Фамилия студента>`, `<факультет>`, `<кафедра>`. Любое поле можно указать и в `meta.yaml` конкретной работы, оно важнее сохранённого профиля.

Перенос на другой компьютер: `report-gen profile export` создаёт `profile.enc`, зашифрованный вашим паролем (не короче восьми символов); `report-gen profile import` восстанавливает данные.

## Как работать

### Курсовой проект

```bash
report-gen init projects/kursach --title "Тема работы"
```

Откроются файлы работы:

| Файл | Что внести |
|---|---|
| `meta.yaml` | тема, дисциплина, год, шифр документа, при необходимости ФИО |
| `brief.md` | своими словами: цель, предметная область, роли, возможности, технологии |
| `sources.txt` | список источников по ГОСТ 7.1, по одному в строке (программа сама источники не придумывает) |
| `screens.yaml` | план скриншотов и диаграмм (примеры внутри файла) |

Папка с кодом вашего проекта подключается только для чтения. С Docker положите проекты в папку, указанную в `REPORTGEN_CODE_DIR` (по умолчанию `./projects`), она доступна внутри контейнера как `/code`.

```bash
report-gen make projects/kursach --code /code/мой-проект
```

`make` снимает скриншоты, пишет разделы, проверяет по стандарту и собирает файлы. Результат лежит в `projects/kursach/output/`: `note.docx`, `tex/note.tex`, `note.pdf`. Скриншоты лежат отдельно, в `projects/kursach/screenshots/`.

Текст разделов хранится в `content/*.md`: его можно править вручную, потом `report-gen build projects/kursach`. Разделы, у которых не менялись данные, заново не генерируются.

### Автоматическая проверка и исправление

После написания разделов программа сама проверяет текст по стандарту и просит модель исправить только те разделы, где есть замечания (не более двух раундов; число раундов задаётся ключом `--rounds`, `--rounds 0` отключает). Оставшиеся замечания выводятся списком.

### Где данных не хватает

Если в сведениях нет нужного факта, модель не выдумывает его, а оставляет метку `[УТОЧНИТЬ: что нужно]`; лишние метки автоматическая проверка убирает. Оставшаяся метка считается ошибкой в `report-gen lint`, пока вы не внесёте данные в `brief.md` и не перегенерируете раздел (`report-gen write <работа> --section <id> --force`).

### Отчёт по лабораторной

```bash
report-gen init projects/lab3 --type lab
report-gen lab projects/lab3 --task /code/task.docx --code /code/мой-проект
report-gen build projects/lab3
```

### Структура по образцу

```bash
report-gen from-sample projects/kursach --sample /code/sample.docx
```

Берутся только заголовки и примерные объёмы. Сам образец автоматически добавляется в эталоны, чтобы новый текст не повторял его дословно.

### Исправление готового документа

```bash
report-gen lint --docx report.docx                       # что не так
report-gen fix report.docx --output report.fixed.docx    # привести к стандарту
report-gen fix report.docx --remarks remarks.txt         # плюс разбор замечаний руководителя в report.fixed.review.md
```

Абзацы после таблиц и рисунков: `report-gen notes <отчет.docx> --output todo.json --images-dir images` выгружает данные объектов, абзацы пишет автор, `python scripts/check_notes.py <абзацы.json> <todo.json>` проверяет их, `report-gen fix ... --notes абзацы.json` вставляет. Пакетная сборка восьми отчетов по NotaCode и все правила владелицы: `docs/ИНСТРУКЦИЯ_СБОРКА_ОТЧЕТОВ.md`.

`fix` по умолчанию меняет только оформление. Переписывание абзацев, совпадающих с эталонами, включается флагом `--reference <папка>`.

### Эталоны для проверки совпадений

Положите работы, на которые нельзя быть похожим, в `workspace/reference/`:

```bash
report-gen overlap projects/kursach/content --reference workspace/reference
```

Абзацы, у которых доля общих пятисловных фрагментов с эталоном выше 25 %, помечаются; при генерации они переписываются автоматически.

## Веб-интерфейс с кнопками

Если удобнее нажимать кнопки, а не вводить команды:

```bash
report-gen ui                          # без Docker
docker compose --profile ui up ui      # с Docker
```

Откройте <http://127.0.0.1:8765>. На странице можно создать работу, снять скриншоты, написать и собрать документы, проверить их по стандарту, скачать DOCX, TeX и PDF, выбрать провайдера моделей и сохранить данные для титульного листа. Работы лежат в папке `projects/` (её можно изменить переменной `REPORTGEN_PROJECTS`).

Интерфейс доступен только с вашего компьютера: он слушает `127.0.0.1`, отклоняет чужие адреса в заголовке Host, требует секретный токен на каждое действие и умеет выполнять только фиксированный набор команд. Ключи на странице не вводятся и не показываются, виден лишь статус «задан» или «не задан».

## Ваш стандарт и ваш стиль

В репозитории лежит краткий свод правил стандарта, написанный своими словами (`src/reportgen/data/guidelines/`), и правила письма для модели. Полный текст вашего стандарта в репозиторий не входит. Если у вас есть PDF:

```bash
report-gen stp ingest "путь/к/стандарту.pdf"     # строит локальный индекс пунктов (в git не попадает)
report-gen stp ask "как оформлять перечисления"  # найти нужные пункты
```

После этого к запросам модели автоматически добавляются выдержки из пунктов, относящихся к пишущемуся разделу.

Свои правила и шаблоны запросов можно положить в `workspace/guidelines/` (файлы с теми же именами, что во встроенной папке): они заменят встроенные.

Профиль стиля по вашим работам: `report-gen style learn "папка/с/вашими/работами"`. Сохраняется только статистика (длина предложений и абзацев, типичные обороты); тексты не хранятся и модели не отправляются.

## Модели и переключение

| Роль | Назначение |
|---|---|
| `writer` | основной текст разделов |
| `rewriter` | переписывание совпадающих абзацев |
| `reviewer` | разбор замечаний руководителя |
| `vision` | описание скриншотов |
| `utility` | служебные задачи |

У каждой роли есть цепочка резервных моделей. Список меняется без правки кода: скопируйте `src/reportgen/data/models.yaml` в `workspace/models.yaml` и отредактируйте.

## Приватность и безопасность

- Ключи хранятся в защищённом хранилище системы или в `.env`; файл `.env` исключён из git.
- Перед отправкой модели из запросов и сообщений об ошибках вырезаются ключи и токены.
- Личные данные, профиль стиля, индекс стандарта и эталонные работы лежат в `workspace/` и в git не попадают.
- Перед каждым коммитом проверка `scripts/check_secrets.py` блокирует `.env`, личные файлы и фрагменты, похожие на ключи. Включите её: `git config core.hooksPath .githooks`.
- Контейнер запускается без прав администратора. Пути рисунков ограничены папкой работы, листинги кода выносятся в отдельные файлы.
- Команды из `screens.yaml` (запуск приложения, консольные снимки) выполняются как есть: используйте только свои файлы работ.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `не задан OPENROUTER_API_KEY` | выполните шаги из раздела про ключи, затем `report-gen key status` |
| `HTTP 429` | бесплатный лимит: подождите; программа сама повторяет и берёт резервные модели |
| `пустой ответ` у модели | модель «думала» дольше лимита; программа повторяет с большим запасом, проверьте `models --check` |
| нет PDF | нужен Docker (`docker compose build`) или XeLaTeX |
| в документе остались `<…>` | заполните `profile set` или `meta.yaml` |
| в тексте `[УТОЧНИТЬ: …]` | допишите факты в `brief.md` и перегенерируйте раздел с `--force` |
| `report-gen doctor` | покажет, чего не хватает в окружении |

## Разработка

```bash
pip install -e ".[dev]"
pytest
ruff check src tests scripts
```

Чтобы продолжить разработку с ИИ-ассистентом в новом чате, приложите [docs/NEXT_CHAT.md](docs/NEXT_CHAT.md): там состояние проекта, принципы работы и список оставшихся задач.

Архитектура: `domain` (правила без ввода-вывода), `application` (сценарии и порты), `infrastructure` (адаптеры), `interface` (CLI). Зависимости направлены только внутрь.

CI (GitHub Actions): линтер, сканирование секретов, тесты на Python 3.10 и 3.12, сборка образа и демонстрационного отчёта. Релиз: тег `vX.Y.Z` публикует пакет, образ в GHCR и GitHub Release.
