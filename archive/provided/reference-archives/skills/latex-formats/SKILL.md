# Оформление содержимого в LaTeX

Правило: используются только команды и окружения, которые уже есть в шаблоне. Ниже образцы для встроенного шаблона (`../assets/latex-template/`). Если шаблон у пользователя свой, сверься с `note-map.md` (скил `analyze-note-sources`).

## Что нужно на входе

Из `coursework-brief.md`: папка сборки, папка рисунков внутри `note/`. Для скриншотов: папка со скриншотами. Пусто: спроси «В какой папке лежат скриншоты интерфейса? Как они названы и в каком порядке идут?»

## Набор текста

- Тире: `слово~-- слово`. Никогда `---`.
- Латинские названия: `\textit{PostgreSQL}`. Подчёркивание в именах: `\textit{telegram\_id}`.
- Ссылки: `на рисунке~\ref{fig:design:er}`, `в таблице~\ref{table:development:indexes}`, `в подразделе~\ref{sec:design:database}`. Перед `\ref` неразрывный пробел.
- Проценты и разряды: `80\,\%`, `23\,930`.
- Источник: `[4]` в конце абзаца.

## Заголовки и метки

```latex
\section{Проектирование системы}
\label{sec:design}

\subsection{Проектирование баз данных}
\label{sec:design:database}

\subsubsection{Порядок работы с инструментом}
```

Введение, заключение, список источников:

```latex
\sectioncentered*{Введение}
\addcontentsline{toc}{section}{Введение}
```

Метки: `sec:<раздел>:<подраздел>`, `fig:<раздел>:<имя>`, `table:<раздел>:<имя>`.

## Перечисления

Простое (тире ставит шаблон):

```latex
\begin{itemize}
	\item первый пункт;
	\item второй пункт.
\end{itemize}
```

Сложное (пункты из предложений):

```latex
\begin{enumerate}
	\item Выбрать из базы данных все активные записи.
	\item Зафиксировать транзакцию.
\end{enumerate}
```

**Вложенное перечисление должно стоять глубже родительского.** Для списков одного типа отступ второго и третьего уровня задан в преамбуле. Для смешанной вложенности (тире внутри нумерованного) пакет `enumitem` считает уровни отдельно по типам, поэтому отступ задаётся явно:

```latex
\begin{enumerate}
	\item Для каждого товара по очереди:
	\begin{itemize}[itemindent=2.2ex,leftmargin=2\parindent,label=--]
		\item пропустить товар без пороговой цены;
		\item сформировать запрос.
	\end{itemize}
	\item Зафиксировать транзакцию.
\end{enumerate}
```

После сборки посмотри страницу: вложенные пункты должны быть сдвинуты вправо относительно родительских.

## Сущность базы данных

```latex
Сущность «Пользователь»
\begin{itemize}
	\item идентификатор~-- первичный ключ, внутренний номер пользователя в системе;
	\item электронная почта~-- адрес для отчётов (может отсутствовать);
	\item дата регистрации~-- момент первого обращения пользователя к системе.
\end{itemize}
```

Название сущности обычным начертанием, без `\textbf`. Форма описания в `../assets/formats.md`.

## Рисунок

```latex
\begin{figure}[H]
	\centering
	\includegraphics[width=\linewidth]{<папка рисунков>/er_chen}
	\caption{\textit{ER}-диаграмма базы данных в нотации Питера Чена}
	\label{fig:design:er}
\end{figure}
```

- Параметр `[H]`: рисунок стоит там, где вставлен, после абзаца с первой ссылкой.
- Файл лежит внутри `note/` (например, `note/attachments/<имя>/`). Диаграммы вставляются в PDF, расширение можно не писать.
- Ширина подбирается по отчёту `render.sh` (скил `diagram-common`): `width=\linewidth`, `0.95\linewidth`, `0.6\linewidth`.
- Подпись без точки в конце. Слово «Рисунок», номер и тире ставит шаблон.
- На каждый рисунок есть ссылка в тексте до него.
- Имена и обозначения в описывающем тексте совпадают с тем, что нарисовано.

## Скриншоты

```latex
\begin{figure}[H]
	\centering
	\includegraphics[scale=0.5]{<папка рисунков>/screens/start.png}
	\caption{Приветствие и главное меню}
	\label{fig:manual:start}
\end{figure}
```

- Масштаб задаётся через `scale`, по умолчанию 50 % исходного размера. Все скриншоты в одном масштабе.
- Файлы пользователя пронумерованы по порядку рисунков. Копируй в папку рисунков с понятными именами и сверь каждый: открой снимок и убедись, что подпись описывает именно его. Ошибка на один файл при копировании сдвигает все подписи.
- Скриншот выше страницы: уменьши масштаб у него и скажи об этом.

## Таблица

Обычная:

```latex
\begin{table}[ht]
\caption{Индексы и обслуживаемые ими запросы}
\label{table:development:indexes}
\centering
	\begin{tabular}{|>{\raggedright}m{0.30\textwidth}
	                |>{\raggedright}m{0.37\textwidth}
	                |>{\raggedright\arraybackslash}m{0.23\textwidth}|}
	\hline
	\centering Индекс & \centering Запрос & \centering\arraybackslash Частота \\
	\hline Товары: владелец & Список товаров пользователя & Каждый диалог \\
	\hline
	\end{tabular}
\end{table}
```

- Подпись над таблицей. Шапка не выделяется жирным.
- Сумма ширин граф около 0,9 от `\textwidth`.

Таблица, которая не помещается на страницу, верстается через `longtable` с продолжением:

```latex
\begin{longtable}{|>{\raggedright}m{0.28\textwidth}|>{\raggedright\arraybackslash}m{0.62\textwidth}|}
\caption{Описание варианта использования «Добавить товар»}
\label{table:design:uc1}\\
\hline
\centering Параметр & \centering\arraybackslash Описание \\ \hline
\endfirsthead
\caption*{Продолжение таблицы \ref{table:design:uc1}}\\ \hline
\centering Параметр & \centering\arraybackslash Описание \\ \hline
\endhead
Идентификатор и название & UC-1 Добавить товар \\ \hline
\end{longtable}
```

- На перенесённой части должно остаться не меньше трёх строк данных. Если получилось меньше, перенеси разрыв выше: поставь `\newpage` перед строкой, с которой должна начинаться новая страница.
- После сборки открой страницы с переносом и проверь.

## Список источников

```latex
[1] Название ресурса [Электронный ресурс].~-- Режим доступа: \textit{https://example.\allowbreak org/\allowbreak page}.~-- Дата доступа: 01.01.2026.
```

В длинных адресах ставь `\allowbreak` после точек и косых черт, иначе адрес вылезет за правое поле (в логе это `Overfull \hbox`). Порядок источников по появлению ссылок в тексте.

## Приложение

```latex
\clearpage
\phantomsection
\begin{center}
	\textbf{ПРИЛОЖЕНИЕ А}\\
	(обязательное)\\
	\textbf{Скрипт создания схемы базы данных}
\end{center}
\appendixtocline{Приложение А (обязательное) Скрипт создания схемы базы данных}

\lstinputlisting{<папка рисунков>/schema.sql}
```

Заголовок приложения оформляет шаблон, жирное начертание здесь штатное. Запись в содержание делает `\appendixtocline`. Листинг подключается из файла, не вставляется в текст.

## Что не делать

- Не создавай новые команды, окружения и пакеты, если хватает существующих.
- Не меняй преамбулу ради одного элемента. Настройки вёрстки описаны в скиле `latex-layout`.
- Не вставляй растровые диаграммы, если есть векторный PDF.
- Не оставляй заглушки рисунков и текста «Текст подраздела» в готовых разделах.
- Не ставь ручные разрывы страниц для красоты; `\newpage` допустим только для правила трёх строк в таблице.

Источник: K1, K4 (только существующие средства шаблона; формат сущности и таблицы сценария), K8 (перенос таблиц, три строки, жирный), K11 (вложенные перечисления), K13 (скриншоты в 50 %), итоги K11 и K23 (явный отступ при смешанной вложенности, переносы в адресах).
