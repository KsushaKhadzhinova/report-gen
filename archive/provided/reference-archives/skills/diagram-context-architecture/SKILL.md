# Диаграммы контекста и архитектуры

Сначала прочитай `diagram-common`. Образцы: `../assets/diagram-tools/examples/context.puml`, `architecture.puml`.

## Что нужно на входе

Из карты проекта (`project-map.md`): внешние системы и роли (для контекста); сервисы, контейнеры, базы данных и способ развёртывания (для архитектуры). Нет: сначала `analyze-project-code`.

## Чем диаграммы отличаются

| | Контекст (C4, уровень 1) | Архитектура развёртывания |
|---|---|---|
| Раздел | 2.2 Проектирование системы | 3.4 Программная реализация |
| Вопрос | с кем и с чем взаимодействует система | из каких частей состоит и как они связаны |
| Система | один блок в центре, внутреннее устройство не раскрывается | раскрыта на сервисы и хранилища |

## Правила для диаграммы контекста

1. В центре один блок системы с названием и одной фразой о назначении.
2. Вокруг: роли пользователей и внешние системы (внешние API, мессенджер, почтовый сервер, СУБД, если она рассматривается как внешняя).
3. На каждой связи подпись: что передаётся и каким способом («Поиск объявлений», «HTTPS, JSON»).
4. Внутренние модули системы не показываются: это следующий уровень.
5. Блоков не больше семи-восьми.
6. Библиотека C4 для PlantUML рисует легенду, свои цвета и набирает подписи технологий курсивом: это особенность библиотеки, допустимо. Шрифт Arial.

## Правила для диаграммы архитектуры

1. Узел развёртывания (сервер, среда контейнеров) и сервисы внутри него; внешние системы снаружи.
2. У каждого сервиса название и основная технология в одну-две строки.
3. Связи подписаны протоколом или видом взаимодействия. Работа с базой подписывается как SQL-запросы; ORM не упоминается, если так записано в брифе.
4. Показаны служебные части, если они есть в проекте: резервное копирование, наблюдение, очередь.
5. До 10–12 блоков. Вспомогательные сервисы, не важные для записки, опускаются.
6. Вертикальная или компактная компоновка; подписи связей не перекрывают блоки.

## Как строить

```bash
cd <папка исходников диаграмм>
cp examples/context.puml context.puml            # замени участников и связи
./render.sh context.puml 0.6 12
cp examples/architecture.puml architecture.puml  # замени сервисы и связи
./render.sh architecture.puml 0.9 12
pdftoppm -r 70 -png architecture.pdf просмотр
```

Контекст обычно вставляется на 0,6 ширины строки, архитектура на 0,9–1,0.

## Согласование с текстом

- Перечень внешних систем в тексте совпадает с диаграммой контекста и с разделом о средствах реализации.
- Названия сервисов на диаграмме архитектуры и в тексте совпадают; версии технологий указываются одинаково везде.
- Числа на подписях (интервал опроса, ограничение частоты) совпадают с текстом требований.
- В тексте к диаграмме контекста есть ссылка на источник о модели C4.

## Проверка

- [ ] на контексте система показана одним блоком;
- [ ] каждая связь подписана;
- [ ] все внешние системы из карты проекта присутствуют;
- [ ] только Arial, кегль на странице не ниже 9 пт;
- [ ] названия и числа совпадают с текстом.
