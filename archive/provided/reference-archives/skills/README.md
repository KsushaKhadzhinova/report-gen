# Набор скилов для пояснительной записки к курсовому проекту

Набор помогает написать пояснительную записку (LaTeX, оформление по СТП БГУИР) по готовому программному проекту. Знать, что внутри скилов, не нужно.

## Как пользоваться

Скажите ассистенту:

> Запусти coursework-start. Проект лежит в `<папка>` (или: вот ссылка на GitHub).

Дальше он сам спросит всё остальное: тему и сведения для титула, файл задания, образец записки, стандарт оформления, шаблон, тезисы, скриншоты. На любой вопрос можно ответить «нет»: для каждого материала есть встроенная замена. Ответы сохраняются в файл `coursework-brief.md`, повторно вопросы не задаются. Работу можно прервать и продолжить той же фразой.

Код проекта считается завершённым и не меняется: записка описывает его как есть.

Полезные фразы по ходу работы:
- «Что дальше?» (этапы и текущее состояние);
- «Напиши раздел 2.1», «Сделай ER-диаграмму», «Сделай схему алгоритма для процесса ...»;
- «Вот замечания руководителя: ...»;
- «Проверь, собирается ли PDF», «Проверь текст», «Закоммить»;
- «Где меняется отступ у ...?»

## Подключение

Скилы должны лежать там, где ассистент их ищет. Для Claude Code в папке проекта:

```bash
mkdir -p .claude/skills
for d in skills/*/; do ln -s "$(realpath "$d")" ".claude/skills/$(basename "$d")"; done
```

Папка `assets` тоже подключается: скилы обращаются к ней как к `../assets/`. Чтобы набор был доступен во всех проектах, сделайте те же ссылки в `~/.claude/skills/`.

## Что нужно установить

Docker (образ для сборки собирается один раз командой `docker build -t neitex:latex .` в папке сборки), PlantUML, Graphviz, `rsvg-convert`, poppler (`pdfinfo`, `pdftotext`, `pdffonts`), Python 3 с Pillow, шрифт Arial, git. Скил `coursework-start` проверяет это сам и говорит, чего не хватает.

## Состав

| Скил | Что делает |
|---|---|
| `coursework-start` | Точка входа: опрос, файл состояния, проверка окружения |
| `coursework-workflow` | Порядок этапов, условия перехода, чек-лист сдачи |
| `analyze-project-code` | Карта проекта: модули, данные, процессы, что реализовано |
| `analyze-note-sources` | Разбор LaTeX-шаблона: какие средства оформления уже есть |
| `analyze-sample-works` | Разбор образца записки и задания: структура, объёмы, форматы |
| `text-sections` | Что писать в каждом разделе |
| `text-style-ru` | Стиль текста и финальная чистка |
| `text-lint` | Автопроверка `.tex` (скрипт `lint_tex.py`) |
| `latex-formats` | Оформление списков, сущностей, рисунков, таблиц, источников, приложений |
| `latex-layout` | Настройка вёрстки: содержание, заголовки, зазоры, титул из PDF |
| `stp-rules` | Правила стандарта и поиск в нём |
| `change-boundaries` | Что можно менять, что нельзя, когда спросить |
| `diagram-common` | Общие правила диаграмм, читаемость, готовые изображения |
| `diagram-er-chen` | ER-диаграмма в нотации Чена |
| `diagram-db-schemas` | Логическая и физическая схемы БД |
| `diagram-usecase` | Варианты использования и таблицы сценариев |
| `diagram-classes` | Диаграмма классов |
| `diagram-sequence` | Диаграмма последовательности |
| `diagram-flowchart-stp` | Схемы алгоритмов по СТП |
| `diagram-context-architecture` | Контекст (C4) и архитектура развёртывания |
| `fix-teacher-remarks` | Правки по замечаниям руководителя |
| `build-check` | Проверка сборки PDF (скрипт `check_build.sh`) |
| `commit-iteration` | Коммит после итерации, только при рабочем PDF (скрипт `commit_iteration.sh`) |

Папка `assets/`:
- `brief-template.md`: шаблон файла состояния;
- `latex-template/`: шаблон записки с пустыми разделами, Makefile и Dockerfile;
- `diagram-tools/`: генератор схем алгоритмов, проверка ER, рендер с отчётом о читаемости, образцы всех видов диаграмм;
- `stp-digest.md`: выжимка стандарта с номерами пунктов;
- `formats.md`: формы описания сущности, сценария, аналога, заключения;
- `prompts/`: два исходных промта, которые используются без изменений.

## Откуда взяты правила

Скилы составлены по промтам из переписки при написании курсовой про Telegram-бота мониторинга объявлений (файлы `промты_курсовой.md` и `prompts_zapiska.md`, номера K и Z). Поздние просьбы отменяют ранние; в скилах записано итоговое состояние. Таблица показывает, в каком скиле лежит каждая просьба.
