# ER-диаграмма в нотации Чена

Сначала прочитай `diagram-common`. Образец: `../assets/diagram-tools/examples/gen_er_chen.py`, проверка: `../assets/diagram-tools/check_er.py`.

## Что нужно на входе

- Из карты проекта (`project-map.md`): сущности, атрибуты, связи и их мощность. Нет: сначала `analyze-project-code`.
- Из брифа: язык диаграммы (по умолчанию русский). Пусто: спроси «ER-диаграмму подписывать по-русски (концептуальная модель) или именами таблиц и столбцов?» и запиши.

## Правила

**Содержание**
1. Это концептуальная модель: сущности, связи и атрибуты названы по-русски и не зависят от имён таблиц. Реальные имена показываются на логической и физической схемах (скил `diagram-db-schemas`).
2. Сущности берутся из реального проекта, а не из шаблона: сверь с картой. Служебные и резервные таблицы на концептуальной диаграмме не показываются.
3. **На диаграмме по три атрибута на сущность:** ключ и два самых характерных. Полный состав атрибутов перечисляется в тексте раздела. С полным набором подписи становятся нечитаемыми.
4. Первичный ключ подчёркнут.
5. Связь изображается ромбом с глаголом: «отслеживает», «порождает», «входит в».
6. Мощность подписана на линиях у сущностей: 1, N, M.
7. Упрощение по просьбе пользователя (убрать связь ради читаемости) допустимо; в тексте оговаривается (скил `change-boundaries`).

**Компоновка**
8. Вертикальная: цепочка главных сущностей идёт сверху вниз по центру, ромбы связей между ними. Сущности, связанные сбоку, вынесены в левую колонку.
9. Атрибуты прижаты к своей сущности: у центральной цепочки справа столбиком, у боковых сущностей **вокруг** (сверху, слева, снизу).
10. **Линии не проходят по овалам и сквозь чужие блоки.** Если атрибуты стоят столбиком с одной стороны, линия к дальнему пройдёт по ближнему: расставь вокруг сущности.
11. Подписи из двух слов переносятся на две строки («пороговая / цена»): овал становится уже.
12. Сбоку от сущности ставь самый узкий овал.
13. Расстояния между блоками минимальные, поля вокруг рисунка убраны.
14. Шрифт Arial, кегль исходника 13. Цель: около 9 пт на странице при вставке во всю ширину.

**Техника**
15. Координаты закреплены: каждый узел имеет `pos="x,y!"`, файл рендерится `neato -n2`. Автоматическая раскладка Graphviz расползается и даёт широкую диаграмму с мелким текстом.
16. Диаграмма задаётся генератором на Python: три таблицы (сущности, ромбы, атрибуты) с координатами в дюймах. Чтобы подвинуть блок, меняется одно число.

## Как строить

```bash
cd <папка исходников диаграмм>
cp examples/gen_er_chen.py gen_er_chen.py
# замени списки ENT, REL, ATTR, LINKS, EDGES своими
python3 gen_er_chen.py            # пишет er_chen.dot
python3 check_er.py er_chen.dot   # наложения и линии сквозь узлы
./render.sh er_chen.dot 1.0 13    # PDF, шрифты, кегль на странице
pdftoppm -r 70 -png er_chen.pdf просмотр
```

Порядок раскладки:
1. Расставь цепочку сущностей по центру с шагом около 2–2,6 дюйма по вертикали, ромбы посередине между ними.
2. Боковые сущности поставь слева на уровне той сущности цепочки, с которой они связаны; ромб связи между ними.
3. Атрибуты цепочки: справа, столбиком с шагом около 0,7 дюйма, средний на уровне сущности.
4. Атрибуты боковых сущностей: один сверху, один слева, один снизу.
5. Запусти `check_er.py`. Пока есть нарушения, двигай узлы.
6. Посмотри картинку: проверка геометрии не видит некрасивых, но формально допустимых мест.

`check_er.py` учитывает форму узлов (прямоугольник, ромб, эллипс). Код возврата 0 означает «нарушений нет».

## Согласование с текстом

- Названия сущностей на рисунке и в заголовках списков атрибутов совпадают дословно.
- Число сущностей в тексте («модель из семи сущностей») совпадает с рисунком и заключением.
- В тексте есть фраза о том, что на концептуальном уровне названия русские, а соответствие таблицам дано при описании логической схемы.
- Если диаграмма подписана именами таблиц (по решению пользователя), то и перечни атрибутов под ней используют те же имена столбцов, курсивом, а в заголовке сущности указывается таблица.
- Связи описаны словами: «один ко многим».

## Проверка

- [ ] `check_er.py`: нарушений нет;
- [ ] только Arial, кегль на странице около 9 пт или больше;
- [ ] ключи подчёркнуты, мощность подписана на каждой связи;
- [ ] диаграмма выше, чем шире;
- [ ] текст раздела совпадает с рисунком.
