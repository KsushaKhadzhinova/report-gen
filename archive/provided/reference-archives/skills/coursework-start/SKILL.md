# Старт работы над запиской

Пользователь может ничего не знать об устройстве набора скилов. От него нужен только готовый проект. Всё остальное этот скил спрашивает сам, по одному небольшому блоку вопросов, и для каждого ответа «нет» есть запасной вариант.

Материалы набора лежат в папке `assets/` рядом с папкой этого скила (`../assets/` относительно этого файла).

## Что нужно на входе

Только одно: готовый проект (ссылка на GitHub или путь к папке). Если пользователь его не назвал, это первый вопрос. Всё остальное запрашивается ниже по шагам.

## Шаг 1. Найти или создать бриф

1. Ищи `coursework-brief.md` в текущей папке и на уровень выше.
2. Если бриф есть: прочитай его, найди первый незакрытый этап и предложи продолжить с него. Задавай только те вопросы, чьи поля пусты.
3. Если брифа нет: спроси, в какой папке вести записку (по умолчанию текущая), скопируй туда `../assets/brief-template.md` под именем `coursework-brief.md`.

## Шаг 2. Опрос

Спрашивай через AskUserQuestion, не больше четырёх вопросов за раз, в этом порядке. Каждый ответ сразу записывай в бриф. Пути проверяй: файл или папка должны существовать, иначе переспроси.

**Блок А. Проект (обязательно)**
- «Где лежит готовый проект: ссылка на GitHub или путь к папке?»
  - Ссылка: `git clone --depth 1 <ссылка> <рабочая папка>/project`. Если клонирование не удалось (приватный репозиторий, нет сети), попроси пользователя склонировать самому и дать путь.
  - Путь: используй как есть, ничего не копируй.
- Предупреди один раз: код проекта считается завершённым и не меняется. Записка описывает его как есть.

**Блок Б. Сведения для титула и задания**
- Тема, дисциплина, вуз, факультет, кафедра, ФИО студента, руководитель, консультант, сроки.
- «Есть ли файл задания (docx или pdf)?» Если есть, прочитай его и возьми оттуда тему, перечень вопросов, перечень графического материала, ограничения. Спрашивай только то, чего в файле нет.
- «Есть ли готовые титульный лист и ЗАДАНИЕ в PDF?» Если да, запиши путь и число страниц: они вставляются как есть (скил `latex-layout`).

**Блок В. Образцы и стандарт**
- «Есть ли образец записки (можно на другую тему)?» Нет: используется `../assets/formats.md`.
- «Есть ли файл стандарта оформления (СТП)?» Нет: используется `../assets/stp-digest.md`.
- «Есть ли свой LaTeX-шаблон?» Нет: скопируй `../assets/latex-template/` в `<рабочая папка>/sources/`.
- «Есть ли тезисы, цифры и факты по предметной области?» Нет: тезисы составляются на этапе 2, а цифры без источника помечаются в брифе как непроверенные.

**Блок Г. Решения по содержанию**
- «Есть ли в задании ограничения по технологиям (запрещённые СУБД, ORM, фреймворки)?» Если в проекте используется ORM, спроси отдельно: «В проекте используется ORM. Как писать в записке: описывать работу с базой через SQL и ORM не упоминать, или упоминать как есть?»
- «Нужен ли подраздел о применении интеллектуальных инструментов?» По умолчанию да.
- «Нужны ли таблицы с описанием вариантов использования?» По умолчанию нет: достаточно диаграммы.
- «Какой целевой объём?» По умолчанию 60 страниц.
- Аналоги для обзора: предложи три после анализа проекта, пользователь подтверждает или заменяет.

**Блок Д. Позже, по мере надобности**
Не спрашивай заранее, а только перед соответствующим этапом:
- папка со скриншотами интерфейса (перед разделом 4);
- готовые диаграммы пользователя, например экспорт схемы из DBeaver (перед этапом диаграмм);
- замечания преподавателя (после первой полной сборки).

**Блок Е. Сборка и фиксация**
- «Фиксировать ли результат в git после каждой итерации?» Если да, выясни корень репозитория (`git rev-parse --show-toplevel`). Если папка записки лежит в общем репозитории, запиши в бриф только пути записки и диаграмм. Если репозитория нет, спроси, создавать ли.

## Шаг 3. Проверка окружения

Проверь наличие инструментов и сообщи одним списком, чего не хватает и как это поставить:

| Что | Проверка | Зачем |
|---|---|---|
| Docker и образ `neitex:latex` | `docker image inspect neitex:latex` | сборка PDF; образ собирается один раз: `docker build -t neitex:latex .` в папке сборки |
| `plantuml`, `dot` (graphviz), `rsvg-convert` | `command -v ...` | диаграммы |
| `pdftotext`, `pdfinfo`, `pdffonts` (poppler) | `command -v ...` | проверки PDF, чтение СТП |
| Python 3 и Pillow | `python3 -c "import PIL"` | схемы алгоритмов |
| Шрифт Arial | `fc-match Arial` должен вернуть Arial | текст на диаграммах |
| `pandoc` или чтение docx | по необходимости | чтение образцов |

Без Docker можно собирать локальным `latexmk` (ключ `--local` у проверки сборки), но шрифты записки могут отличаться. Запиши выбранный способ в бриф.

Собери пустой шаблон скилом `build-check` и запиши в бриф базовое число Overfull. Если пустой шаблон не собирается, чини окружение до начала работы над текстом.

## Шаг 4. Маршрут

Отметь этап 0 выполненным и переходи к скилу `coursework-workflow`: он задаёт порядок этапов и условия перехода. Коротко скажи пользователю, что будет дальше и что от него понадобится (подтвердить тезисы, дать скриншоты, посмотреть диаграммы).

## Правила опроса

- Не задавай вопрос, если ответ есть в брифе, в файле задания или однозначно виден в проекте.
- Не выдумывай сведения для титула, цифры и факты. Нет данных: оставь поле пустым и занеси в «Открытые вопросы».
- Один вопрос имеет один смысл. Варианты ответа давай готовые, первым ставь рекомендуемый.
- После опроса покажи пользователю краткую сводку брифа одним списком.
