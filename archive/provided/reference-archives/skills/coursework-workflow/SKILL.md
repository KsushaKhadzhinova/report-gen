# Последовательность работы над запиской

Сначала прочитай `coursework-brief.md`. Нет брифа: запусти `coursework-start`.

## Что нужно на входе

`coursework-brief.md` с отметками этапов. Если пользователь просит конкретный раздел или диаграмму, а предыдущие этапы не закрыты (нет карты проекта, нет согласованных тезисов, нет нужной диаграммы), скажи, чего не хватает, и предложи сделать это сначала. Недостающие файлы и решения запрашивает скил соответствующего этапа.

Работа идёт итерациями. Итерация: один раздел, одна диаграмма или один пакет правок. Каждая итерация заканчивается одинаково:

1. `build-check`: PDF собирается.
2. `text-lint`: нет ошибок в изменённых файлах.
3. `commit-iteration`: фиксация, если в брифе включена.
4. Отметка в брифе и короткий отчёт пользователю: что сделано, число страниц, что осталось открытым.

## Этапы и условия перехода

| Этап | Что делается | Скилы | Нельзя идти дальше, пока нет |
|---|---|---|---|
| 0. Опрос | бриф, окружение, пустой шаблон собирается | `coursework-start`, `build-check` | брифа с путём к проекту и собранного шаблона |
| 1. Анализ | карта шаблона, форматы образца, карта проекта | `analyze-note-sources`, `analyze-sample-works`, `analyze-project-code` | `project-map.md` с разделами «реализовано» и «не реализовано» |
| 2. Тезисы | тезисы по каждой главе, перечень диаграмм, три аналога | `text-sections` (и промт `../assets/prompts/z4_theses_and_diagrams.md`) | согласия пользователя с тезисами и перечнем диаграмм |
| 3. Диаграммы | все диаграммы из перечня | `diagram-common` и скил нужного вида | PDF каждой диаграммы с отчётом о читаемости |
| 4. Разделы | текст по одному разделу | `text-sections`, `text-style-ru`, `latex-formats` | диаграмм, на которые раздел ссылается |
| 5. Целое | стыки разделов, нумерация, источники, приложения, титул | `latex-formats`, `latex-layout` | полной сборки без ошибок и неразрешённых ссылок |
| 6. Чистка | финальный проход по стилю | `text-style-ru`, `text-lint` | ошибок линтера: ноль |
| 7. Замечания | правки руководителя | `fix-teacher-remarks` | закрытых пунктов замечаний |
| 8. Сдача | чек-лист ниже | `build-check` | выполненного чек-листа |

Порядок разделов на этапе 4: введение, 1.1, 1.2, 1.3, 2.1, 2.2, 3.1, 3.2, 3.3, 3.4, 4, заключение, список источников, приложения. Заключение пишется после всех глав, потому что отчитывается по цели из введения.

Допустимо писать несколько разделов подряд по одной просьбе пользователя, но сборка и проверка выполняются после каждого.

## Что обязательно на каких этапах

- **До любого текста:** карта проекта. Текст опирается только на то, что реально реализовано.
- **До раздела 2.1:** ER-диаграмма и логическая схема. **До 2.2:** варианты использования, контекст, последовательность, схемы алгоритмов. **До 3.2:** физическая схема. **До 3.4:** архитектура и диаграмма классов. **До раздела 4:** скриншоты (спроси папку).
- **После каждого изменения рисунка:** обновить текст и подписи, которые его описывают.
- **После удаления раздела, рисунка, таблицы:** вычистить все упоминания, проверить перечень в листе задания.
- **Перед финальной чисткой:** весь текст написан. Чистка идёт в два прохода при большом объёме: главы 1–2, затем 3–4 и заключение.

## Как работать с пользователем

- Запись результата идёт сразу в файлы записки, заменяя прежнее содержимое раздела. Отдельные черновики не создаются.
- Перед разделом скажи, на какие тезисы и материалы опираешься. После раздела скажи, что вошло, и перечисли сомнительные места.
- Просьбу пользователя выполняй в её границах (скил `change-boundaries`). Заметил проблему за пределами просьбы: опиши и спроси.
- Принятый результат («идеально», «не менять», «оставь как есть») заноси в реестр «Не трогать» в брифе.
- Противоречие между новой просьбой и прежним правилом: действует новая. Запиши решение в бриф.

## Чек-лист перед сдачей

- [ ] `build-check` проходит: PDF собран, ошибок LaTeX нет, неразрешённых ссылок нет, Overfull не больше базового.
- [ ] `text-lint` без ошибок; места «ПРОВЕРЬ» просмотрены, сомнительные числа показаны пользователю.
- [ ] Содержание: номера страниц по правому краю, приложения оформлены, лишних записей нет.
- [ ] Каждый рисунок и таблица имеют ссылку в тексте и стоят после первой ссылки.
- [ ] Имена на рисунках совпадают с именами в описывающем тексте.
- [ ] Перечень вопросов и графического материала в задании совпадает с фактическим составом записки.
- [ ] Заключение умещается на одну страницу и написано в настоящем времени.
- [ ] Список источников: на каждый источник есть ссылка, адреса не вылезают за поле.
- [ ] Объём близок к целевому из брифа.
- [ ] В брифе нет открытых вопросов без ответа; непроверенные цифры показаны пользователю.
