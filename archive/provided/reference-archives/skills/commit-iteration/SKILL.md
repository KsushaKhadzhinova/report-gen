# Коммит после итерации

Цель: в истории лежат только рабочие состояния записки. Каждый коммит соответствует PDF, который собирается.

## Что нужно на входе

Из `coursework-brief.md`, раздел «Сборка и фиксация»:
- включены ли коммиты. Поле пустое: спроси один раз «Фиксировать ли результат в git после каждой итерации?» и запиши ответ. Ответ «нет»: скил ничего не делает;
- папка сборки;
- пути для коммита: папка записки и папка исходников диаграмм. Пусто: определи и запиши (см. ниже);
- ветка. Пусто: спроси, работать в текущей ветке или создать отдельную, запиши.

## Что считается итерацией

Один выполненный запрос пользователя: написанный раздел, одна диаграмма с обновлённым текстом, один пакет правок по замечаниям, одна настройка вёрстки. Несколько несвязанных изменений подряд: несколько итераций и несколько коммитов.

## Запуск

```bash
<папка скила>/scripts/commit_iteration.sh \
  -s <папка сборки> -m "<что сделано>" [-t "<завершающие строки>"] \
  -- <путь записки> <путь диаграмм>
```

Скрипт по порядку:
1. Запускает проверку сборки (`build-check`). Не прошла: отказ, коммита нет.
2. Запускает автопроверку текста (`text-lint`). Есть ошибки: отказ, коммита нет.
3. Добавляет в индекс только перечисленные пути и показывает состав.
4. Отказывает, если в индекс попали сборочные файлы (`.aux`, `.log` и подобные).
5. Делает коммит только по этим путям с сообщением `записка: <что сделано> (N стр., Overfull M)`.

Ключ `--dry-run` показывает состав и сообщение без коммита. Используй его при первом запуске в новом репозитории и покажи результат пользователю.

## Правила

- **Сломанное состояние не коммитится.** Сборка не прошла: исправь и повтори. Не удалось исправить: сообщи пользователю, что именно сломано, и оставь изменения незакоммиченными.
- **Только свои пути.** Никогда `git add -A` и `git add .` из корня. Записка часто лежит в общем репозитории с другими предметами; чужие изменения, даже уже подготовленные к коммиту, не трогаются и в коммит не попадают.
- **Пути определяются один раз.** `git rev-parse --show-toplevel` даёт корень. Если корень выше папки записки, в бриф записываются пути записки и диаграмм относительно корня.
- **Ошибки автопроверки не обходятся молча.** Ключ `--skip-lint` допустим только если пользователь явно согласился оставить найденное (например, слово «мои» в названии кнопки). Причину укажи в сообщении коммита.
- **Сообщение описывает сделанное**, а не процесс: «раздел 2.1 и ER-диаграмма», «правки по замечаниям: тире, перечисления», «схемы алгоритмов по СТП».
- **Завершающие строки.** Если в среде задано, чем заканчивать сообщения коммитов (например, строка Co-Authored-By), передай её ключом `-t`.
- **Не делается:** `push`, `--amend`, `--no-verify`, перезапись истории, коммит кода описываемого проекта. Отправку на сервер выполняй только по прямой просьбе.
- **Нет репозитория:** спроси, создавать ли (`git init`). Без согласия не создавай.
- **Сборочный мусор не коммитится.** Если скрипт отказал из-за файлов вроде `__pycache__/` или `.aux`, добавь их в `.gitignore` рабочей папки (а не удаляй проверку) и повтори.
- **Собранный `note.pdf` коммитится** вместе с исходниками: по нему видно состояние записки на каждом шаге. Сборочные файлы должны быть в `.gitignore` (образец в `../assets/latex-template/.gitignore`).
