# Эталонные форматы (форма без содержания)

Используются, когда пользователь не дал образец работы. Если образец есть, форму берут из него (скил `analyze-sample-works`), а этот файл служит проверкой.

## Список атрибутов сущности (подраздел 2.1)

Название сущности отдельной строкой обычным начертанием, затем перечисление через тире: имя атрибута, тире, пояснение назначения. Точка с запятой в конце пункта, точка после последнего.

```latex
Сущность «Пользователь»
\begin{itemize}
	\item идентификатор~-- первичный ключ, внутренний номер пользователя в системе;
	\item электронная почта~-- адрес для отчётов (может отсутствовать);
	\item дата регистрации~-- момент первого обращения пользователя к системе.
\end{itemize}
```

Правила:
- название сущности в ёлочках и с прописной буквы; жирным не выделяется;
- в пояснении указывается роль атрибута: ключ, уникальность, допустимость пустого значения, зачем нужен;
- на концептуальном уровне (ER в нотации Чена) атрибуты названы по-русски; при описании логической схемы имена столбцов латиницей курсивом (`\textit{telegram\_id}`);
- после списков всех сущностей идёт описание связей и их мощности словами: «один ко многим», «многие ко многим».

## Таблица описания варианта использования (подраздел 2.2)

Делается только если пользователь подтвердил, что таблицы UC нужны. Двухколоночная таблица, по одной на сценарий.

| Строка | Что писать |
|---|---|
| Идентификатор и название | `UC-1 Добавить отслеживаемый товар` (название глаголом) |
| Основное действующее лицо | роль из диаграммы вариантов использования |
| Предварительные условия | что должно быть выполнено до начала |
| Основной поток | нумерованные короткие шаги «актёр делает, система отвечает» |
| Расширения | отклонения от основного потока с номером шага: «3а. Лимит исчерпан: система сообщает об этом» |
| Выходные условия | состояние системы после успешного завершения |

Формулировки короткие, без кода и без имён функций. Внутри таблицы ничего не выделяется жирным. Длинная таблица верстается через `longtable` с «Продолжение таблицы».

## Разбор аналога (подраздел 1.2)

Для каждого аналога четыре части подряд: что это, как работает, достоинства, недостатки. После всех аналогов сравнительная таблица по одним и тем же критериям и вывод о свободной нише.

## Заключение

Одна страница, настоящее время, без «был/была/было». Порядок абзацев:
1. Цель достигнута: что спроектировано и реализовано (одной-двумя фразами).
2. Что показал анализ предметной области и аналогов.
3. Что сделано в проектировании и реализации базы данных: модель, нормализация, индексы, целостность.
4. Что реализовано в программной части из перечня в задании.
5. Направления развития (из списка «чего пока нет» в карте проекта).

## Таблица задач, решённых с интеллектуальными инструментами (подраздел 3.3)

Три графы: «Задача», «Результат работы инструмента», «Что потребовало проверки». По одной строке на задачу: проектирование модели данных, подбор индексов, разбор внешних данных, миграции, тесты, графический материал.
