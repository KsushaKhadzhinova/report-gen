Исходники диаграмм -- в `diagrams/src/` (формат Graphviz `.dot` и PlantUML `.puml`), их можно
править и перегенерировать:

```bash
dot -Tpng -Gdpi=150 src/logical.dot -o out.png     # схемы БД и ER
plantuml -tpng src/classes.puml                    # UML-диаграммы
```

Для вставки в Word: все файлы PNG, 150–160 dpi, ширина рассчитана на альбомную вставку или
масштабирование по ширине страницы. Если нужен вектор для листа А3 -- заменить `-Tpng` на `-Tsvg`.

## Что проверить у консультанта

В задании (`reference/Записка.docx`, последняя страница) есть блок **«Ограничения»** со списком:
СУБД -- Microsoft Access, Firebird, SQLite; технологии -- CRM, **ORM**, django и подобные;
десктопное приложение. Формулировка не поясняет, запрет это или перечень допустимого.

Если это **запрет**, важно для нашего проекта:
- PostgreSQL в списке нет -- выбранная СУБД проходит в любом прочтении;
- SQLite в проекте используется только для локальных тестов, в продакшене его нет;
- **ORM (SQLAlchemy) в проекте используется** -- это единственный пункт, который может
  потребовать согласования либо переписывания части запросов на чистый SQL;
- десктопного приложения нет, Django нет.

## Возможности из задания и где они реализованы

В задании перечислены возможности («Программная реализация приложения»). Там, где через косую
черту дан выбор («csv / xml», «word / excel / pdf»), реализован один вариант -- выбор обоснован в
тезисах к разделу 3.1.

| Возможность | Статус | Где в проекте |
|---|---|---|
| Вход для пользователя | Есть | Идентификация по Telegram, регистрация при первом обращении |
| Вход для админа | Есть | `ADMIN_TELEGRAM_IDS`: повышенный лимит, системный отчёт |
| Работа с БД: поиск, сортировка, вставка, удаление | Есть | `services/products.py`, `services/users.py` |
| Защита данных | Есть | Ключ API, экранирование, лимит частоты, валидация, хеш кода подтверждения почты, защита CSV от инъекции формул |
| Аналитика данных | Есть | Статистика в профиле, отчёт «Найденные предложения» (итоги, средняя выгода), системный отчёт администратора |
| Работа с json | Есть | Импорт фильтров из ссылки, JSON-поля, API |
| Работа с csv / xml (экспорт-импорт) | Есть -- **CSV** | «Мои товары» → «📤 Экспорт CSV» / «📥 Импорт CSV»; `services/transfer.py`, `GET /users/{id}/export`, `POST /users/{id}/import` |
| Отчёты word / excel / pdf | Есть -- **Excel** | `/report` или «Профиль» → «📊 Отчёт в Excel» (7/30/90 дней); `services/reports.py`, `reports/excel.py`; отчёт можно получить и письмом |
| Мультиязычный интерфейс | Есть -- русский и английский | Язык определяется по Telegram при регистрации, меняется в «⚙️ Настройки» или `/language`; хранится в `users.language`; словари `i18n/ru.py`, `i18n/en.py`. Уведомления и отчёты -- тоже на языке пользователя |
| Использовать e-mail | Есть | «⚙️ Настройки» → «✉️ Почта»: привязка с кодом подтверждения, копии уведомлений на почту (сводным письмом), отправка отчётов вложением; `services/mail.py`, `services/email_account.py`, `notifications/email_sender.py` |
| Корзина, история заказов, скидки | Неприменимо к предметной области | -- |

Для демонстрации почты в `docker compose` поднят **Mailpit** -- почтовый ящик-ловушка: все письма
бота видны в браузере по адресу http://127.0.0.1:8025, реальный ящик не нужен. Для настоящей
отправки достаточно указать в `.env` SMTP-сервер (Gmail, Яндекс) и пароль приложения -- код не
меняется.

### Что показать на защите (порядок демонстрации)

1. `/language` → English: меню, кнопки и сообщения переключаются; обратно на русский.
2. «Мои товары» → «📤 Экспорт CSV»: файл открывается в Excel по колонкам, кириллица читается.
3. Удалить товар, «📥 Импорт CSV» с тем же файлом -- товар вернулся; строки с ошибками
   перечислены с номерами.
4. `/report` → 30 дн.: файл `.xlsx` с листами «Находки» и «Итоги», ссылки кликабельны,
   работает автофильтр.
5. «⚙️ Настройки» → «✉️ Почта» → ввести адрес → письмо с кодом появляется в Mailpit →
   ввести код; затем «✉️ На почту: 30 дн.» в меню отчётов -- письмо с вложением.
