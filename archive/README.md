# Архив контекста проекта report-gen

Эта папка создана для нового ИИ-ассистента и нового чата: здесь полный ход работы и все материалы, которые дала владелица проекта. Лежит только в ветке `context-archive`, в `main` её нет. После завершения проекта владелица удалит ветку (`git push origin --delete context-archive`).

Содержит личные работы владелицы и материалы университета. Не копируйте их в другие репозитории и не отправляйте в модели без прямой просьбы владелицы.

## С чего начать новому ассистенту

1. Прочитайте этот файл целиком.
2. Прочитайте `docs/NEXT_CHAT.md` в ветке `main` (архитектура, принципы, что осталось по коду).
3. Прочитайте раздел «Решения владелицы» ниже: это то, что нельзя пересматривать без вопроса.
4. Раздел «Статус» покажет, что уже собрано, а что нет.
5. Сырой диалог (`dialog/session-transcript.jsonl`) читайте только для уточнения деталей: файл большой, поиском по ключевым словам.

Правила работы владелицы: отвечать по-русски; перед правкой файлов, запуском команд и любыми необратимыми действиями спрашивать разрешения; коммиты от её имени без строк соавторства; не использовать дорогие модели без разрешения; шумит ноутбук, поэтому тяжёлые процессы (Docker, Word, Ollama) запускать по одному и только когда нужно.

## О чём проект

`report-gen` (репозиторий https://github.com/KsushaKhadzhinova/report-gen, локально `E:\zapiska-gen`) собирает и исправляет отчёты, курсовые и лабораторные по СТП БГУИР из одного источника в форматах DOCX, LaTeX и PDF. Работает из терминала и браузера без ассистентов. Модель по умолчанию облачная бесплатная (OpenRouter), есть Gemini, локальная Ollama и любой OpenAI-совместимый сервер. Недостающие сведения не выдумываются, а помечаются `[УТОЧНИТЬ]`.

## Главная срочная задача

Отчёты по предмету «Электронный бизнес» (папка `E:\ИИТ\ЭлектронныйБизнес\СДАЧА`, 8 файлов) нужно довести до идеального оформления по СТП и требованиям ВАК РБ, показать владелице картинки страниц и выгрузить DOCX и PDF в репозиторий E-Business (ветка «финал», папка СДАЧА) только после её явного «всё ок».

## Решения владелицы (не пересматривать)

Оформление и содержание:
- Заголовки разделов в тексте и в оглавлении пишутся прописными буквами.
- Из оглавления убрана запись «Отчёты ЛР1–ЛР4».
- Из текста убраны разговорные вставки-«вода» (список фраз в `FILLER_PHRASES`, файл `docx_objects.py`).
- Источники-сайты оформляются по образцу ВАК РБ: `Название : [сайт]. – URL: адрес (дата обращения: дд.мм.гггг).` Запись со списком сайтов делится на отдельные записи.
- Источник «Отчеты по лабораторным работам» из списков удаляется.
- Ссылки `[1–3]` в тексте убираются везде, оставшиеся номера сдвигаются на 3 (в ЛР1, ЛР5 и ЛР7 сдвиг ровно 3; это владелица подтвердила).
- Длинные таблицы режутся на страницы с подписью «Продолжение таблицы N», заголовок таблицы повторяется.
- Загружать в E-Business только после её «всё ок»; перед этим показывать страницы картинками.

Работа:
- В папках её учебных проектов ничего не менять и не создавать (результаты складывать в отдельные: `E:\ПРОВЕРКА`, `E:\ИСПРАВЛЕННЫЕ`, `E:\ОТЧЕТЫ АВТО`, `E:\ОТЧЕТЫ ТЕСТ`).
- Имена в коде только английские, без транслита русских слов; чистый код и чистая архитектура (Р. Мартин); без «ИИ-комментариев» в коде.
- Коммиты от её лица; никаких строк соавторства.
- Её ключи доступа ассистент не читает и не выводит: они хранятся в Диспетчере учётных данных Windows (`report-gen key set …`), у неё в терминале.
- Личные данные в репозитории проекта (`main`) только заглушки; настоящие в локальном `workspace/profile.yaml`. Для этой ветки владелица сознательно разрешила публичную загрузку своих материалов.

## Как устроены главные части кода

- `src/reportgen/infrastructure/docx_objects.py`: исправление объектов DOCX (титульная дата, заголовки, подписи, рисунки, таблицы, список источников, перенумерация ссылок).
- `src/reportgen/infrastructure/docx_format.py`: аудит DOCX по правилам СТП с учётом наследования стилей.
- `src/reportgen/domain/citations.py`, `sources.py`, `fix_options.py`: ссылки, формат источников ВАК, параметры исправления.
- `scripts/word_finalize.ps1`: Word через COM (оглавление, разбиение таблиц, экспорт PDF); запускать по одному документу, иначе ноутбук шумит и зависает.
- `scripts/finalize_reports.py`: пакетная обработка отчётов.
- `scripts/check_secrets.py` и `.githooks/pre-commit`: блокировка секретов; `scripts/prepare_archive.py` скрывает ключи в архиве.
- Подробная карта слоёв и принципов: `docs/NEXT_CHAT.md` в `main`.

## Известные ловушки

- Word без экрана: убивать только свои зависшие процессы WINWORD.
- Оболочка у владелицы PowerShell 7; команды для неё писать в синтаксисе PowerShell (не bash).
- Heredoc портит обратные слеши; правки больших файлов делать скриптом на Python с обработкой CRLF.
- Лимиты бесплатных моделей: при исчерпании дневного лимита клиент сообщает время сброса и останавливается.
- Модель сочиняет имена файлов проекта, поэтому в сводку кода подставляются реальные имена.
- Отчёты «Электронный бизнес» исходно имеют несогласованные ссылки (сдвиг на 3 между текстом и списком, обрезанный список в ЛР6); аудит это показывает, исправлять без данных владелицы нельзя.
